# 当前状态

重做结果报告的内容模型。先交付纯文本样稿供用户评审，认可后再改 JSON 和网页。

- 最近一次 JSON 校验、17 项 Python 单测、16 组画像关键断言均通过。
- 当前结果页文案是未验收草稿，不能用于商业发布。

## 已确认的失败模式

- 主结论没有直接说“偏滋养/偏消耗/并存”；用户真实结果应是“整体偏滋养，同时夹杂少量消耗”。
- “有现实支撑”“一处需要观察”“没有某种感受突出”等表达含糊、虚假精确或像没有结果。
- 文案经常把题目选项换句话复述，缺少付费用户期待的新增洞察。
- 低来源只能作为次级解释，不能抢占主结论。
- “保留自己”“符合你的需要”等话太抽象；必须落到真实想法、朋友兴趣、生活节奏或具体行动。
- 维度 `repair` 的用户文案应为“产生矛盾后能否一起解决”。

## 下一轮验收标准

- 一级结果至少覆盖：明显偏滋养、整体偏滋养但夹杂消耗、滋养与消耗并存、整体偏消耗、信息不足；标题直接包含滋养/消耗语义。
- 不说“一处/几处”；只表达整体倾向和相对程度。
- 完整报告依次回答：结论、跨题依据、关系模式、可能的心理状态或应对方式、影响判断和投入的因素、具体行动。
- 洞察必须来自多个答题信号，可追溯但不逐项复述；不得诊断依恋、人格或疾病。
- 行动建议直接具体，例如：“写下你现在最希望对方做到的一件具体事情，再看它最近有没有真实发生。”

## 下一步

1. 核对当前规则是否能稳定形成五级滋养/消耗结论。
2. 提出“洞察不是复述”的生成规则。
3. 先给两份完整纯文本样稿：用户真实结果（整体偏滋养、夹杂少量消耗，矛盾处理相对弱，五因素均低）和明显偏消耗对照。
4. 用户认可后才修改 JSON、网页和验证脚本。
