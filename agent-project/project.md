# 关系能量测试

## 产品目标

面向仍在恋爱、暧昧、断联、考虑复合或分手后难以放下的人，制作一款可在小红书销售的低客单价手机端自我觉察测试。商业路径是用几十种痛点笔记持续指向同一款产品，而不是频繁开发新测试。

- 主标题：这段关系，是在滋养你，还是在消耗你？
- 传播副题：你舍不得的，是他，还是那个没有完成的结局？
- 用户购买的不是诊断，而是一个能解释迷茫、让自己被看见、获得下一步线索并适合表达分享的低价答案。
- 产品价值优先级高于工程包装：先保证结果“被说中”、有新增解释且值得付费，再优化正式网页。
- 首版纯前端本地计算，不收集姓名、手机号、聊天记录等非必要信息。

## 用户希望得到什么

1. 先明确知道关系整体更偏滋养、偏消耗，还是两者并存。
2. 理解为什么自己会安心、疲惫、反复或舍不得。
3. 看见由多道答案共同反映出的相处模式和应对方式，而不是看到选项被换句话复述。
4. 得到两三条具体、低风险、能直接执行的观察或行动建议。
5. 获得值得付费、适合截图分享，但不羞辱、不绝对化的报告。

## 成功标准

- 题目自然、具体，选项覆盖常见情况且不预设关系有问题。
- `ongoing` 与 `ended` 只使用适用题计分；NA 不计分，场景外答案不污染结果。
- 一级结果必须直接回答滋养/消耗；信息不足只在有效答案确实不足时出现。
- 次级解释回答“什么在影响你的判断和投入”，不能反客为主。
- 洞察来自跨题组合、反复模式、内在矛盾、保护策略和现实代价；不能复述单个选项。
- 可克制地描述可能的心理状态或应对方式，但不诊断依恋类型、人格或疾病。
- 报告语言必须让用户一遍读懂：每句补足宾语、指代和比较对象，不依赖未出现的前文，不用抽象咨询腔或机械复述选项。
- 洞察只能写触发证据确实支持的模式，不补写用户动机、不预设自责或关系有问题；行动建议注明适用条件，进行中与已结束关系分别处理。
- 避免相邻句重复同一个词或结论；标题负责情绪共鸣，正文负责解释，报告引用句负责文学性收束，不再重复分析。
- 不伪造效度、准确率、专家背书或用户评价。
- 主 JSON、Python 计分器、内部网页工具和测试必须保持规则一致；正式上线前完成真实认知访谈与移动端验收。

## 当前模型与工程约束

- 总题库 28 道四选一情境题；仍在关系中展示 25 道，关系已结束展示 16 道（共用 13 道通用题）；可选 NA，近期题权重 1.25。
- 关系层内部键：`reciprocity`、`stability`、`repair`、`selfPreservation`；另计算 `sustainability`。
- 影响判断和投入的因素：`memory`、`potential`、`intermittent`、`validation`、`loss`。
- 两层独立计分；双向生长只适用于 `ongoing`，`ended` 只回看过去的相处。
- 当前阈值是首版产品规则，待真实访谈校准，不代表心理测量学效度。

## 产品边界

- 自我觉察与娱乐内容，不构成心理、医疗、法律或关系决策建议。
- 不替用户决定分手或复合；不对伴侣作人格判断。
- 若涉及暴力、威胁、强控制、跟踪或人身风险，优先提示可信赖的人、当地紧急服务和专业支持。
- 内部验证不能代替真实用户对准确感、价值感和分享意愿的评价。
- 题目、报告和界面文案由用户亲自审校；除非用户明确点名要求修改，否则后续工程与视觉工作必须原样保留现有文字。
